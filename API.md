# API Contract

Base path: `/api`

The MVP does not have authentication. All application endpoints operate in the context of the one seeded development user.

## Health

### GET `/api/health`

Response:

```json
{ "status": "ok" }
```

## Extract preview

### POST `/api/applications/extract-preview`

Request:

```json
{
  "url": "https://example.com/jobs/software-engineer"
}
```

Response example:

```json
{
  "sourceUrl": "https://example.com/jobs/software-engineer",
  "companyName": "Example Corp",
  "jobTitle": "Software Engineer",
  "companyWebsiteUrl": "https://example.com",
  "shortDescription": "Build and maintain web applications...",
  "skills": ["TypeScript", "React", "PostgreSQL"]
}
```

Important:

- `sourceUrl` is supplied by the user, not generated by AI.
- Do not include `dateApplied` in AI output.
- The preview is not persisted.

## Create application

### POST `/api/applications`

Request:

```json
{
  "sourceUrl": "https://example.com/jobs/software-engineer",
  "companyName": "Example Corp",
  "jobTitle": "Software Engineer",
  "companyWebsiteUrl": "https://example.com",
  "shortDescription": "Build and maintain web applications...",
  "skills": ["TypeScript", "React", "PostgreSQL"],
  "status": "APPLIED"
}
```

Server behavior:

- resolve current user
- validate all fields
- set `dateApplied = now()` unless an explicit future edit endpoint is introduced
- default status to `APPLIED`
- resolve/create skills and link them
- persist the application

Response: created application resource.

## List applications

### GET `/api/applications`

Initial query parameters:

- `status` optional
- `q` optional text search across company/job title
- `page` optional, default 1
- `limit` optional, default 25

Response shape:

```json
{
  "data": [],
  "meta": {
    "page": 1,
    "limit": 25,
    "total": 0,
    "pageCount": 0
  }
}
```

## Get one

### GET `/api/applications/:id`

Return the application including its skills.

## Update

### PATCH `/api/applications/:id`

Allow editing:

- company name
- job title
- source URL
- company website URL
- short description
- skills
- status
- date applied

The update must confirm that the record belongs to the current user.

## Delete

### DELETE `/api/applications/:id`

Delete one application belonging to the current user.

## Error conventions

Use normal HTTP semantics and a predictable JSON error shape from NestJS. Validation errors should be explicit enough for the frontend to show useful feedback without exposing internal stack traces.

## Future auth compatibility

When authentication is introduced, the route shapes should remain stable. Only the source of the current user identity should change.
